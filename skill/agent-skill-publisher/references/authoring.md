# 从经验整理技能

先找会反复出现、且确实改变操作决策的经验。一次错误可成为有条件的诊断规则，不应无限扩大成所有任务的审批或限制。创建时无需用户再次提供已在会话中的案例。

区分四层：

- **通用技能**：何时使用、如何推进任务、资源和运行依赖。
- **客户端适配**：安装位置、额外元数据、包根结构、工具是否可用。
- **专家包装**：角色、头衔、市场文案、推荐提问、嵌入技能与头像。
- **项目配置**：公司端点、联系人、业务规则、偏好模型；除非技能本来是私有项目技能，否则不进入公开包。

推荐用“输入与意图 → 关键判断 → 必要工具 → 交付和验证”的方式写正文。机器名稳定，展示名先说平台/用途；简介写能力与触发条件，长介绍写场景、输入示例和交付，不让人物昵称遮住产品名称。

参考资料按需读取；脚本负责容易重复出错的确定性操作。一个实用技能不需要固定数量的文档。不要把聊天日志、旧包、缓存、全部测试数据和开发笔记塞入安装包。公开仓库 README/CHANGELOG 与技能正文分开。

通用 frontmatter 的 `name` 与目录名对应，description 非空；扩展字段按目标 schema 保留。YAML 字符串建议加引号，尤其是数字版本、冒号和特殊字符。构建器使用真实 YAML 解析并拒绝重复键；不以正则子串存在冒充字段有效。

新技能应自包含。依赖另一个技能时，只有确实必要并有安装/发现证据才建立依赖；仅参考知识可总结到本包并保留来源，不要求用户另装作者机器上的技能。不要承诺某个桌面 Agent 自带所有脚本运行时、浏览器、MCP 或联网权限。

标准结构依据 [Agent Skills 规范](https://agentskills.io/specification)；平台专属约定见 [平台矩阵](platforms.md)。本项目提供工具的使用范围，不冒充各平台官方校验器。
