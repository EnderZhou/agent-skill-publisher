# 开源发布与更新

用户明确要求新建 GitHub 开源项目时，可以在其已认证账号创建 public 仓库并发布本任务成果。先完成可审查源码、许可、候选包和验证，再提交。普通“整理技能”不自动授权开源；已有授权不重复询问。

选择稳定英文机器名，记录 author、许可证、版本和反馈入口。仓库 README 面向使用者说明用途、目标客户端、安装方式、依赖与验证边界；CHANGELOG 记录变化，Release 放版本化 ZIP、清单和 SHA256。技能自身的 references 解决操作问题，不用 README 替代 SKILL.md。

发布前：

1. 检查新仓库候选内容与 diff，保留第三方许可。公开包不带公司端点、原始对话日志、凭据、员工信息或用户资产数据。参数示例用虚构域名。
2. 跑本地验证和必要测试，记录每个客户端尚未验证的阶段。不能把一个客户端成功扩大为全平台成功。
3. 分清版本：技能、专家外壳、嵌入技能与目标客户端分别记录，更新展示名称不改稳定 ID。修复导入错误可补丁升级。
4. 优先可用连接器；它不能建库/上传 Release 资产时用已认证 GitHub CLI，不寻找或打印令牌。确认当前账号与目标仓库；不操作无关仓库。
5. 将多行发布说明写入文件，使用 `--notes-file` 或结构化参数，不把正文拼进 Shell 执行文本。
6. 新建仓库、提交、推送、创建版本标签与 Release 后，读回默认分支 commit、可见性、标签和资产列表；下载 Release ZIP 对照本地 SHA256。检查失败时报告实际结果，不写已发布。

GitHub 常用步骤为 `gh repo create owner/name --public --source ... --remote origin`、`git push -u origin main` 与 `gh release create vX.Y.Z ... --notes-file ...`。这是经授权发布的操作清单，不是读取本技能即可执行的授权。组织所有权、可见性或同名仓库有歧义时先核对，不覆盖现有项目。

本地安装用已确认的客户端技能目录；保存原版本到发现目录之外，核对哈希后更新。不要把备份放在另一个会被扫描的 skills 子目录。发布物不可变；修复用新版本或明确标注重发，不悄悄替换同版本内容。回滚保留旧包与旧版本清单。
