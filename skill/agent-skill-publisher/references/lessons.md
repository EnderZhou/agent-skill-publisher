# 实际案例与适用边界

| 观察到的问题 | 采取的方法 | 规则适用范围 |
| --- | --- | --- |
| 专家卡片没有直观突出 FastGPT/N8N | 名称、头衔、简介和标签均明确平台，详细介绍写场景与交付 | 专家展示策略，非所有技能命名强制模板 |
| FastGPT 专家展示名 17 字，上传器上限 15 字 | 用 12 字短名称，检查两种语言，同步 Agent 元数据；稳定机器标识不变 | 2026-11-05 WorkBuddy 上传反馈；英文同限是保守选择 |
| 普通技能 ZIP 缺少市场字段 | 在 WorkBuddy 打包副本增加八项必填元数据 | WorkBuddy 技能市场；不覆盖通用源 frontmatter |
| 深层模板使独立技能 ZIP 被拒 | 先规划映射与引用/加载器改造，检测冲突，解压后验证功能 | 曾观察到两段路径限制的上传入口；专家结构另验 |
| ZIP 看起来完整，但资源引用失效 | 对实际 ZIP 检查引用，再从独立目录执行关键脚本 | 静态链接检查不能覆盖动态构造路径 |
| 专家包技能版本落后 | 读取最新清单并验证包哈希，单独记录专家与技能版本 | 不因为专家升级而虚增内置技能版本 |
| 同一包改名后被称作多平台适配 | 生成明确的根入口/目录/市场格式，分别记录发现、执行与审核 | 标准格式兼容不等于全平台实测 |
| 测试只在源码目录成功 | 解压真实发行包后验证，避免依赖未打包脚本 | 不对未知不可信包自动执行其自检 |
| Windows 与容器环境差异 | 确认可用 Python/uv、UTF-8、实际 home/profile 和工作目录 | 不把某台电脑绝对路径写进公开技能 |

这些案例来自维护者实际生成技能与专家时的反馈，已移除内部业务资料。未包含上传成功或市场审核通过的证据，不能据此声称 WorkBuddy 已完成全流程验收。未来新反馈应补日期和影响范围，避免将偶然现象积累为无条件限制。
