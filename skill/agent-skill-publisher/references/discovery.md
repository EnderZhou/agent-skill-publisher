# 名称、简介与搜索发现

为技能与专家撰写或修改展示文案时使用。先从实际能力、适配平台和用户会搜索的任务词提炼内容，不以泛泛的“Agent专家”或人物昵称遮住用途。

- 名称优先“平台或多平台 + Skill/技能/专家 + 生成/排错/发布”等明确用途，短而能看懂。只有真实支持时才用“一键”等结果承诺。
- 简介开头列出已适配平台的标准拼写和实际用途，例如 WorkBuddy、Trae、Codex、Claude Code、Cursor、GitHub Copilot、Hermes 等等；“等等”表示可继续评估扩展，不等于已支持所有未知平台。
- 区分技能适配与专家生成：本项目其他客户端适配的是技能，WorkBuddy 同时支持技能和专家。不得为了搜索流量混淆范围。
- 名称长度不足以列出全部平台时，优先保留用途；在完整简介、关键词、标签、推荐提问和详细介绍补齐平台清单。不要突破上传器上限，或新增不受支持的字段。
- WorkBuddy 专家名控制15字符；卡片简介40–50字符；标签和推荐提问各三条。平台清单装不下时卡片写主要平台加“等”，详细介绍列全。技能市场简介可详述，机器名维持稳定。
- 关键词可覆盖平台正式名称和常见别称、Skill/Skills/技能、生成、打包、导入排错、适配、发布等相关词。仅在实际schema允许的位置填写，不重复堆词或承诺搜索排名。
- 双语文案语义一致；检查实际生成包内名称、卡片与正文是否同步，并区分格式校验、客户端实测、市场上架的状态。
